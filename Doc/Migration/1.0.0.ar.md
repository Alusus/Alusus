# الأسس 1.0.0: ملاحظات الترحيل للمشاريع التابعة

هذه الوثيقة موجهة للمطورين ووكلاء الذكاء الاصطناعي الذين يحدّثون المكتبات والمشاريع المبنية على الأسس من الإصدار
0.16.0 إلى مترجم ومكتبة معيارية الإصدار 1.0.0. تقتصر الوثيقة على التغييرات التي قد تمنع ترجمة الشفرة الموجودة أو
تغيّر سلوكها، وعلى كيفية تحديث الشفرة. أما الميزات الجديدة التي لا تؤثر على الشفرة الموجودة فمذكورة في
`changelog.ar.md`، وصفحات مرجع الواجهات البرمجية موجودة تحت `Doc/Srt_Reference/`.

تُذكر الأسماء العربية لعناصر الشفرة مع أسمائها الإنجليزية بين قوسين. تُعرض الأمثلة بالصيغتين العربية والإنجليزية
حيث يختلف التحديث بينهما.

## 1. تغييرات في الصياغة

### لم يعد الأمر `عرف` (`def`) يقبل الصيغة `عرف اسم: صنف = قيمة`

لم يعد الأمر `عرف` (`def`) يقبل المؤثر `=`، فشفرة مثل:

```
عرف العدد: صحيح = 0؛
عرف الاسم: نـص = "الأسس"؛
```

```
def count: Int = 0;
def name: String = "Alusus";
```

أصبحت تفشل بالخطأ:

```
CD1003: Invalid 'def' command.
```

استخدم الأمر الجديد `متغير` (`var`) بدلا منها:

```
متغير العدد: صحيح = 0؛          // يُنشأ دون معطيات ثم تُسند إليه القيمة 0.
متغير الاسم: نـص = "الأسس"؛
متغير المجموع = أ + ب؛          // يُستنتج الصنف من القيمة.
```

```
var count: Int = 0;
var name: String = "Alusus";
var total = a + b;
```

مقابلة الشفرة القديمة بالجديدة:

| 0.16.0 | 1.0.0 |
|---|---|
| `عرف س: ص = ق؛` (`def x: T = v;`) | `متغير س: ص = ق؛` (`var x: T = v;`)، أو `متغير س = ق؛` (`var x = v;`) لاستنتاج الصنف |
| `عرف س: ص(معطيات)؛` (`def x: T(args);`) | دون تغيير. وتصلح أيضا `متغير س: ص(معطيات)؛` (`var x: T(args);`). |
| `عرف س: ص؛` (`def x: T;`) | دون تغيير. |

ملاحظات:

- تحافظ الصيغة `متغير س: ص = ق` (`var x: T = v`) على معنى الصيغة القديمة `عرف س: ص = ق`: يُنشأ المتغير دون
  معطيات ثم تُسند إليه القيمة `ق`. لتمرير القيمة إلى دالة التهيئة بدلا من ذلك استخدم `متغير س := ق`
  (`var x := v`) مع استنتاج الصنف، أو `متغير س: ص(ق)` (`var x: T(v)`). أما `متغير س: ص := ق`
  (`var x: T := v`) فخطأ (SPPH1027).
- ينطبق هذا أيضا على المتغيرات الأعضاء (`متغير أ: صحيح = 3؛` داخل صنف) وعلى المتغيرات المشتركة (`@مشترك`).
- المتغيرات العمومية المعرفة بـ`متغير` (`var`) تُسند إليها قيمها في دالات التهيئة العمومية، فيُضمَّن الإسناد في
  البناء المسبق (الملفات التنفيذية) أيضا.

### كلمات مفتاحية جديدة: `متغير` (`var`) و`ضمن` (`within`)

أصبحت `متغير` و`var` و`ضمن` و`within` كلمات مفتاحية. يجب تغيير اسم أي معرّف يحمل أحد هذه الأسماء ويُستخدم في بداية
جملة.

## 2. تغييرات في الشمول

### اشمل `المترجم` (`compiler`) بدلا من ملفات القلب ونبم المنفردة

لم تعد ملفات مكتبة التعامل مع المترجم تشمل ما تعتمد عليه، وهي `الـقلب` (`Core`) و`الـقلب/أسـاسيات`
(`Core/Basic`) و`الـقلب/شـبم` (`Core/Ast`) و`نـبم` (`Spp`) و`نـبم/شـبم` (`Spp/Ast`). شمول أحدها وحده يفشل الآن
بأخطاء مثل `SPPA1007: Unknown symbol.` تظهر داخل ملف المكتبة نفسه.

استبدلها بشمول واحد:

```
اشمل "المترجم"؛
```

```
import "compiler";
```

على سبيل المثال:

```
// 0.16.0
اشمل "الـقلب/شـبم"؛
اشمل "نـبم"؛

// 1.0.0
اشمل "المترجم"؛
```

```
// 0.16.0
import "Core/Ast";
import "Spp";

// 1.0.0
import "compiler";
```

شمول ملفات مـتم (`Srl`) مثل `مـتم/نـص` و`مـتم/طـرفية` لم يتغير.

### أصبحت `نعم` (`true`) و`لا` (`false`) من الصنف `ثنائي` (`Bool`)

أصبحت `نعم` و`لا` معرّفتين كـ`1ص1` و`0ص1` (`1i1` و`0i1`)، أي من الصنف `ثنائي` (`Bool`، أي `طبيعي[1]`) بدلا من
أن تكونا قيمتين صحيحتين عاديتين. إسنادهما إلى متغيرات صحيحة ما زال يعمل، لكنهما قد تختاران دالة مختلفة عند
وجود عدة دالات بالاسم نفسه، فقد يختار الاستدعاء `د(نعم)` الآن الدالة `د(ثنائي)` بدلا من `د(صحيح)`.

### أصبحت `الـعملية.النظام` و`الـعملية.اللغة` و`الـعملية.مسار_القلب_التنفيذي` ثوابت

أي `Process.platform` و`Process.language` و`Process.coreBinPath`. لم يعد ممكنا الإسناد إليها، فالشفرة التي كانت
تغيّر قيمها (في الاختبارات مثلا) يجب أن تستخدم متغيرا خاصا بها بدلا من ذلك.

### تواقيع `مـتم.نـظام` (`Srl.System`)

أصبحت `نـظام.هات_متغيرا_محيطيا` (`System.getEnv`) تُرجع `مـؤشر_محارف_حرفي` (`CharsLptr`) (انظر القسم التالي).
تخزين النتيجة في `مـؤشر_محارف` (`CharsPtr`) ما زال يعمل لأن `مؤشر_حرفي` (`lptr`) يُحوَّل ضمنيا إلى `مؤشر` (`ptr`).

## 4. سلاسل المحارف الحرفية والصنف `مؤشر_حرفي` (`lptr`)

أصبحت سلاسل المحارف الحرفية من الصنف `مؤشر_حرفي[مصفوفة[طبيعي[8]]]` (`lptr[array[Word[8]]]`)، واسمه المستعار
`مـؤشر_محارف_حرفي` (`CharsLptr`)، بدلا من `مؤشر[مصفوفة[طبيعي[8]]]` (`ptr[array[Word[8]]]`). يُحوَّل `مؤشر_حرفي`
ضمنيا إلى `مؤشر`، فتمرير سلسلة حرفية إلى معطى من الصنف `مـؤشر_محارف` (`CharsPtr`) أو إسنادها إلى متغير من هذا
الصنف ما زال يعمل. أما ما يتعطل فهو:

- تحويل `مؤشر` إلى `مؤشر_حرفي` يجب أن يكون صريحا. الشفرة التي تسند `مـؤشر_محارف` إلى متغير استُنتج صنفه من سلسلة
  حرفية (مثلا `متغير ن = "س"؛ ن = م؛` حيث `م` من الصنف `مـؤشر_محارف`) تفشل الآن بالخطأ
  `SPPG1015: Incompatible types for the given operator.` عرّف المتغير من الصنف `مـؤشر_محارف` بدلا من ذلك
  (`متغير ن: مـؤشر_محارف = "س"؛`)، أو حوّل القيمة صراحة.
- الشفرة التي تفحص صنف سلسلة حرفية (`"أبج"~صنف` (`~type`)، أو معطيات القوالب المستنتجة من سلاسل حرفية، أو
  الماكروهات التي تولد أصنافا من قيم حرفية) تحصل الآن على `مؤشر_حرفي[...]`.
- أصبحت سلاسل المحارف الحرفية تُحوَّل ضمنيا إلى `نـص` (`String`). مجموعات الدالات التي تقبل مؤشرا و`نـص` معا ما
  زالت تفضل دالة المؤشر، لكن الدالة التي لها نسخة تقبل `نـص` فقط ونسخة أخرى تقبل صنفا آخر يمكن تحويل السلسلة
  الحرفية إليه قد تصبح ملتبسة الآن.

## 5. تغييرات في سلوك المترجم

### أعضاء الكائن متاحة من داخل الدالات الأعضاء دون `هذا.` (`this.`)

أصبح `هذا` (`this`) محقونا ضمنيا في متن كل دالة عضو. يُبحث عن الأسماء داخل الدالة العضو بالترتيب التالي:
المتغيرات المحلية للدالة ومعطياتها، ثم أعضاء الكائن، ثم كل ما هو خارج الصنف. هذا يعني أن **الدالة العضو التي كانت
تشير إلى تعريف عمومي يطابق اسمه اسم أحد أعضاء الصنف أصبحت تشير إلى العضو بصمت**. على سبيل المثال:

```
عرف العدد: صحيح؛
صنف ص {
    عرف العدد: صحيح؛
    عملية هذا.زد() { العدد = 7 }  // 0.16.0: العدد العمومي. 1.0.0: هذا.العدد.
}
```

```
def count: Int;
class C {
    def count: Int;
    handler this.inc() { count = 7 }  // 0.16.0: global `count`. 1.0.0: `this.count`.
}
```

راجع الدالات الأعضاء التي تستخدم أسماء عمومية هي أيضا أسماء لأعضاء في الصنف، وحدد مسارها الكامل (مثلا
`رئيسي.العدد` (`Main.count`)، أو `الـجذر.العدد` (`Root.count`) للتعريفات في المستوى الأعلى). وإن كان يجب ألا يكون
العضو متاحا ضمنيا فعلّمه بالمبدل الجديد `@لا_يحقن` (`@not_injected`).

تغييرات متعلقة بالبحث عن الأسماء:

- لم تعد الحقن (injections) داخل متن الدالة تحجب معطيات الدالة أو تعريفاتها المحلية.
- الاسم الذي يُعثر عليه عبر حقنة أو جملة `استخدم` (`use`) أو نطاق خارجي لم يعد يحجب التعريفات التي تحمل الاسم نفسه
  في النطاقات الأبعد إن لم يطابق المعطيات الممررة. الشفرة التي كانت تعتمد على تعريف داخلي غير مطابق لإظهار خطأ، أو
  على ترتيب حجب معين، قد تُربط الآن بتعريف مختلف.

### عمليات `كمؤشر` (`as_ptr`) و`حدد_مؤشر` (`set_ptr`) المسماة تعرّف دالات داعمة

أصبحت `عملية هذا.د() كمؤشر { ... }` (`handler this.f() as_ptr { ... }`) تعرّف أيضا دالة عضوا باسم `_د` (`_f`)
وتجعل المؤشر `د` يشير إليها. وينطبق الأمر نفسه على عمليات `حدد_مؤشر`. ويترتب على ذلك:

- الصنف الذي يحتوي أصلا عضوا باسم `_د` بجانب عملية `كمؤشر` أو `حدد_مؤشر` باسم `د` أصبح يُظهر الخطأ
  `SPPA1005: Multiple matches were found for the given callee`. غيّر اسم العضو الموجود.
- إعادة تعريف مؤشرين لهما الاسم والصنف نفسهما من عضوين مختلفين في الصنف نفسه (كما في الوراثة المتعددة حيث يحتوي
  كلا الأبوين على مؤشر `د`) أصبحت خطأ، لأن كلتا إعادتي التعريف ستعرّفان `_د`. اجعل هذه المؤشرات تشير يدويا إلى
  دالات بأسماء مختلفة.

### المبدل `@دون_ربط` (`@no_bind`) يُطبَّق عند الوصول الصريح إلى العضو

أصبح المبدل `@دون_ربط` يُطبَّق أيضا عند الوصول إلى العضو صراحة، وليس فقط عبر الحقن. مع
`@دون_ربط متغير جدول: سند[جـدول]؛` (`@no_bind var vtable: ref[VTable]`) أصبح `ك.جدول.هات_قيمة()`
(`t.vtable.getVal()`) يستدعي `هات_قيمة` مع `ك` كـ`هذا` بدلا من `ك.جدول`. الشفرة التي كانت تصل إلى عضو معلَّم
بـ`@دون_ربط` صراحة وتتوقع أن يكون العضو نفسه هو `هذا` يجب تحديثها.

### `~حجم` (`~size`) يُرجع `طـبيعي_متكيف` (`ArchWord`)

أصبح `ص~حجم` (`T~size`) يُرجع دائما `طـبيعي_متكيف` (`ArchWord`) بدلا من أصغر صنف صحيح بإشارة يتسع للحجم. إسناده
إلى `صحيح` (`Int`) ما زال يعمل، لكن انتبه إلى:

- تمرير قيم `~حجم` إلى الدالات متغيرة المعطيات مثل `طـرفية.اطبع` (`Console.print`): استخدم `%ld` (أو حوّل القيمة
  إلى `صحيح`) بدلا من `%d`.
- خلط `~حجم` مع قيم بإشارة في المقارنات أو الطرح، إذ أصبحت تُحسب بعمليات حسابية دون إشارة.

### الاستدعاءات على الأصناف تختار أفضل تطابق

أصبح الاستدعاء على صنف مثل `صـنفي(...)` (`MyType(...)`) يأخذ في الاعتبار دالات التهيئة، ومؤثرات `()` على الصنف
نفسه (`هذا_الصنف` (`this_type`))، ومؤثرات `()` على الكائن (`هذا` (`this`)) معا، ويختار أفضل تطابق بينها. سابقا كان
أول مؤثر `()` يُعثر عليه هو المختار حتى لو طابقت دالة تهيئة بشكل أفضل. الأصناف التي تعرّف الاثنين قد تُربط فيها
هذه الاستدعاءات الآن بدالة مختلفة. إذا تساوى مؤثر `()` ودالة تهيئة في جودة التطابق فإن المؤثر `()` ما زال هو
المختار.

### أخطاء البناء ورموز الخروج

- أصبح البرنامج التنفيذي `alusus` يخرج برمز فشل كلما ظهر خطأ أثناء بناء البرنامج، حتى لو نُفذت الأجزاء التي بُنيت
  بنجاح. السكربتات وأنظمة التكامل المستمر التي كانت تشغّل برامج فيها أخطاء بناء معروفة ومتجاهَلة ستحصل الآن على رمز
  خروج يدل على الفشل. أصلح هذه الأخطاء.
- لم يعد التنفيذ يتوقف عند أول خطأ بناء. الجمل التي تلي خطأ البناء، بما فيها جمل `تمهيد` (`preprocess`)، تُنفذ إذا
  بُنيت هي وما تعتمد عليه بنجاح. لذا قد يختلف خرج البرامج التي فيها أخطاء بناء عما كان عليه في 0.16.0.

## 6. شجرة البنية المجردة والتعامل مع المترجم

### استُبدل `MergeList` بـ`ضـمن` (`Within`)

أُزيل الصنف `Core.Ast.MergeList`. الشفرة التي كانت تنشئ `MergeList` لإضافة عدة عناصر دفعة واحدة، من داخل جملة
`تمهيد` (`preprocess`) مثلا أو عبر `نـبم.مدير_شبم.أضف_عنصرا_قابلا_للدمج`
(`Spp.astMgr.addPossiblyMergeableElement`)، يجب أن تنشئ `الـقلب.شـبم.ضـمن` (`Core.Ast.Within`) بدلا منه:

```
// 0.16.0
def assignments: SrdRef[MergeList] = newSrdObj[MergeList];

// 1.0.0
var assignments: SrdRef[Within] = newSrdObj[Within];
```

```
// 1.0.0
متغير الإسنادات: سـندنا[ضـمن] = أنشئ_كائنا_مشتركا[ضـمن]؛
```

لاحظ أن `سـندنا` (`SrdRef`) يتطلب `اشمل "مـتم/سندات"؛` في الملفات العربية.

تفكك `أضف_عنصرا_قابلا_للدمج` و`احشر_شبم` (`insertAst`) عناصر `ضـمن` بالطريقة نفسها التي كانت تفكك بها `MergeList`.
وإن كان لـ`ضـمن` مسار محدد فإن عناصره تُضاف إلى النطاق الذي يشير إليه ذلك المسار.

### أعضاء أصناف شجرة البنية المجردة أصبحت خصائص

أصبحت لأصناف `الـقلب.شـبم` (`Core.Ast`) و`نـبم.شـبم` (`Spp.Ast`) دالات وصول مولَّدة لأعضائها (مثلا
`تعريف.الاسم.القيمة` (`def.name.value`)). الشفرة الموجودة التي تمر عبر `ربـط` (`Binding`) و`احـتواء_معجمي`
(`MapContaining`) ما زالت تعمل. التغيير الوحيد الذي يجب الانتباه إليه هو في العقد النصية (`مـعرف` (`Identifier`)
و`نـص_حرفي` (`StringLiteral`) وغيرهما)، إذ أصبح العضو `القيمة` (`value`) دالة وصول بدلا من متغير عضو عادي. قراءة
`عقدة.القيمة.القيمة` (`node.value.value`) لم تتغير، لكن الشفرة التي كانت تعتمد على تخطيط الصنف في الذاكرة (مثل
`~حجم` هذه الأصناف، أو الحشو المحسوب من `TiStr~size`) يجب تحديثها.

### تغيير اسم `target` في `تـعريف` (`Definition`) إلى `الموضوع` (`subject`)

في السي++ (`Definition::getTarget`/`setTarget` ← `getSubject`/`setSubject`) وفي شفرة الأسس (اسم العضو `"target"`
في استدعاءات `ربـط` (`Binding`)، أو الخاصية الجديدة `الموضوع` (`subject`))، أصبح هدف التعريف يُسمى `subject`.

## 7. امتدادات السي++

هذا القسم يخص فقط المشاريع التي توسّع المترجم بالسي++.

- تغيّر اسم `Core/Basic/ti_functions.h` إلى `Core/Basic/ti_callees.h`. وأُزيلت دوال المساعدة البطيئة `call()`
  ونسخ إعادة التعريف `TiCallee*`.
- أصبحت الدالات المربوطة مؤشرات دالات عادية بدلا من `std::function`، ولم تعد تستلم المعطى الأول
  `TiFunctionBase *base`. حدّث دالات إعادة التعريف من:
  ```
  static void _f(TiFunctionBase *base, TiObject *self, ...);
  ```
  إلى:
  ```
  static void _f(TiObject *self, ...);
  ```
- استُبدل `useCallee(base)(...)` بـ`callSuper(...)` على ذاكرة الربط (binding cache) التي حددت إعادة التعريف. عرّف
  ذاكرة ربط للدالة في الامتداد، واربطها بـ`init(owner, &Extension::_f)` في `initBindingCaches` الخاصة بالامتداد،
  واستدعِ `this->f.callSuper(...)` لاستدعاء التنفيذ الذي أُعيد تعريفه.
- إعادات التعريف المحددة عبر ذاكرة ربط تُزال تلقائيا عند إتلاف الذاكرة، فلم تعد هناك حاجة لهياكل `Overrides` التي
  كانت تُرجعها `extend` وتُمرر إلى `unextend`. إزالة الوسيط الديناميكي للامتداد تزيل إعادات التعريف الخاصة به.
- استُبدل `Core::Ast::MergeList` بـ`Core::Ast::Within`، وأصبحت لـ`Seeker` عملية جديدة `add` يمكن إعادة تعريفها
  لدعم أنواع أخرى من أهداف `ضمن` (`within`).

انظر `Sources/Spp/RootScopeHandlerExtension.{h,cpp}` لمثال كامل على النمط الجديد.

## 8. قائمة التحقق لتحديث مشروع تابع

1. ابنِ المشروع بمترجم الإصدار 1.0.0.
2. استبدل `عرف اسم: صنف = قيمة` بـ`متغير اسم: صنف = قيمة` (`def name: type = value` ←
   `var name: type = value`). ابحث عن أخطاء `CD1003` للعثور على ما تبقى منها.
3. غيّر أسماء المعرّفات المسماة `متغير` أو `var` أو `ضمن` أو `within`.
4. استبدل شمول `الـقلب` و`الـقلب/أسـاسيات` و`الـقلب/شـبم` و`نـبم` و`نـبم/شـبم` (`Core` و`Core/Basic` و`Core/Ast`
   و`Spp` و`Spp/Ast`) بـ`اشمل "المترجم"؛` (`import "compiler";`).
5. استبدل `Spp.AstNode` بـ`الـقلب.شـبم.عـقدة` (`Core.Ast.Node`)، و`MergeList` بـ`ضـمن` (`Within`)، و`target`
   في التعريف بـ`الموضوع` (`subject`).
6. في الشفرة العربية، استبدل `صح` و`خطأ` و`خطا` بـ`نعم` و`لا`، وأسماء `تطبيق` الخاصة بالمعاجم بمقابلاتها من
   `معجم` (القسم 3).
7. أزل أي إسناد إلى `الـعملية.النظام` أو `الـعملية.اللغة` أو `الـعملية.مسار_القلب_التنفيذي`.
8. أصلح التحويلات الصريحة من `مؤشر` إلى `مؤشر_حرفي` التي يُبلَّغ عنها بالخطأ `SPPG1015` (القسم 4).
9. راجع الدالات الأعضاء التي تشير إلى أسماء عمومية تُستخدم أيضا لأعضاء الصنف (القسم 5)، والأعضاء المسماة `_د`
   بجانب عمليات `كمؤشر` أو `حدد_مؤشر` المسماة `د`.
10. تحقق من نصوص التنسيق التي تطبع قيم `~حجم`.
11. لامتدادات السي++، اتبع القسم 7.
12. شغّل اختبارات المشروع وتأكد أن رمز الخروج صفر، إذ أصبحت أخطاء البناء تؤدي إلى فشل التشغيل.
