# دليل مكتبة `نـبك` (Oop)

مكتبة `نـبك` (نمط البرمجة الكائنية) تضيف الوراثة والدالات الافتراضية إلى الأصناف. الدالة الافتراضية هي دالة يمكن
للصنف المشتق أن يستبدلها بنسخته الخاصة. عند استدعاء الدالة على كائن تُنفذ نسخة صنف الكائن الفعلي، حتى لو كان الاستدعاء
عبر سند إلى صنف أب. على سبيل المثال، يمكن لدالة تستلم أي `شـكل` أن تستدعي عليه `المساحة()` وتحصل على النتيجة الصحيحة
سواء كان الشكل مستطيلا أو مربعا أو غير ذلك.

لاستخدام المكتبة يجب شمولها:

```
اشمل "نـبك"؛
```

```
import "Oop";
```

فقرات **خلف الكواليس** تشرح ما تفعله هذه الماكروهات عند تطبيقها على الأصناف، وهي مفيدة لمعرفة ما تضيفه هذه
الماكروهات على الأصناف المستهدفة وتأثيرها على الأداء، لكنها ليست ضرورية لمعرفة طريقة استخدام هذه الماكروهات.

## تعريف الدالات الافتراضية

لإضافة دالات افتراضية إلى صنف:

1. أضف `نـبك.عرف_جدول_دالات[جدول، جـدول]؛` إلى متن الصنف. `جدول` و`جـدول` اسمان من اختيارك، لكنك ستحتاج لتكرارهما
   في الأصناف المشتقة، لذا فالأسهل أن تستخدم هذين الاسمين دائما.
2. عرّف كل دالة افتراضية كما تعرّف أي وظيفة عادية باستخدام `عملية`، ثم أضف `ضمن جـدول` قبلها و`كمؤشر` بعدها.

```
صنف شـكل {
    نـبك.عرف_جدول_دالات[جدول، جـدول]؛

    عرف الاسم: مـؤشر_محارف؛

    ضمن جـدول عملية هذا.المساحة(): عائم[64] كمؤشر؛

    ضمن جـدول عملية هذا.صف() كمؤشر {
        طـرفية.اطبع("%s: %f\ج"، هذا.الاسم، هذا.المساحة())؛
    }
}
```

```
class Shape {
    Oop.defVtable[vtable, VTable];

    def name: CharsPtr;

    within VTable handler this.area(): Float[64] as_ptr;

    within VTable handler this.describe() as_ptr {
        Console.print("%s: %f\n", this.name, this.area());
    }
}
```

الدالة الافتراضية التي ليس لها متن، كالدالة `المساحة` في المثال السابق، هي دالة مجردة، أي دالة يُتوقع من كل صنف مشتق
أن يوفرها. لا يجوز استدعاؤها على كائن لا يوفرها صنفه.

يشير `هذا` ضمن هذه الدالات إلى الكائن كما في الوظائف العادية، وتُستدعى هذه الدالات بنفس طريقة استدعاء الوظائف العادية،
كما في `ش.صف()`. يمكن أيضا أن تكون الخصال والمؤثرات افتراضية، كما في `ضمن جـدول عملية هذا.الأضلاع: صحيح كمؤشر { ... }`
و`ضمن جـدول عملية هذا + (ع: صحيح): صحيح كمؤشر { ... }`.

**خلف الكواليس:** يتم الوصول إلى دالات الصنف عبر جدول من مؤشرات الدالات يسمى جدول الدالات (vtable). يعرّف
`عرف_جدول_دالات` صنفا اسمه `جـدول` لهذا الجدول، ونسخة مشتركة واحدة منه اسمها `sجدول` (حرف `s` متبوعا بالاسم الأول
المعطى للماكرو)، ومتغيرا عضوا اسمه `جدول` يشير إلى تلك النسخة المشتركة. كل `ضمن جـدول عملية ... كمؤشر` تضيف مؤشر دالة
إلى `جـدول` مع الدالة التي يشير إليها. المتغير `جدول` محقون، لذا يمكن استدعاء المؤشرات مباشرة على الكائن، ومعلَّم
بـ[دون_ربط](../lang_reference.ar.md#ربط-الأعضاء-بالكائن-الحاوي-دون_ربط--no_bind)، لذا تستلم الدالات الكائن في `هذا`
بدل جدول الدالات. ولأن الدالات معرفة داخل `جـدول` فإن `هذا` سيكون عادة من صنف `جـدول`، لذا تغير المكتبة صنفه إلى
صنف الكائن المالك لجدول الدالات. انظر [مؤشرات الوظائف](../lang_reference.ar.md#مؤشرات-الوظائف) لمزيد من التفاصيل
عن `كمؤشر`.

## وراثة صنف

لوراثة صنف ذي دالات افتراضية أضف `نـبك.اشتق_صنفا` إلى متن الصنف المشتق مع إعطائه:

* اسما للمتغير العضو الذي يحمل جزء الكائن العائد للصنف الأب، مثل `شكل`.
* الصنف الأب، مثل `شـكل`.
* نفس الاسمين اللذين أعطيا لـ`عرف_جدول_دالات` في الصنف الأب.

لاستبدال دالة افتراضية من الصنف الأب عرّفها بنفس طريقة تعريفها في الصنف الأب، لكن أضف اسم المتغير العضو قبل اسم
الدالة، كما في `هذا.شكل.المساحة()`، واستخدم `حدد_مؤشر` بدل `كمؤشر`. يمكن للصنف المشتق أيضا أن يضيف دالات افتراضية
جديدة خاصة به باستخدام `كمؤشر` بنفس الطريقة المتبعة في الصنف الأب:

```
صنف مـستطيل {
    نـبك.اشتق_صنفا[شكل، شـكل، جدول، جـدول]؛

    عرف العرض: عائم[64]؛
    عرف الارتفاع: عائم[64]؛

    عملية هذا~هيئ() {
        هذا.الاسم = "مستطيل"؛
    }

    ضمن جـدول عملية هذا.شكل.المساحة(): عائم[64] حدد_مؤشر {
        أرجع هذا.العرض * هذا.الارتفاع؛
    }

    ضمن جـدول عملية هذا.مربع_القطر(): عائم[64] كمؤشر {
        أرجع هذا.العرض * هذا.العرض + هذا.الارتفاع * هذا.الارتفاع؛
    }
}
```

```
class Rect {
    Oop.inheritClass[shape, Shape, vtable, VTable];

    def w: Float[64];
    def h: Float[64];

    handler this~init() {
        this.name = "rect";
    }

    within VTable handler this.shape.area(): Float[64] set_ptr {
        return this.w * this.h;
    }

    within VTable handler this.diagonal2(): Float[64] as_ptr {
        return this.w * this.w + this.h * this.h;
    }
}
```

يشير `هذا` ضمن هذه الدالات إلى كائن `مـستطيل`. يمكن استخدام أعضاء الصنف الأب، مثل `الاسم`، مباشرة على `مـستطيل`،
ويمكن تمرير `مـستطيل` حيثما يُتوقع `سند[شـكل]`. استدعاء دالة افتراضية عبر ذلك السند ينفذ نسخة `مـستطيل`:

```
دالة اطبع_شكل(ش: سند[شـكل]) {
    ش.صف()؛
}

عرف م: مـستطيل؛
م.العرض = 2؛
م.الارتفاع = 3؛
اطبع_شكل(م)؛ // يطبع: مستطيل: 6.000000
```

```
func printShape(s: ref[Shape]) {
    s.describe();
}

def r: Rect;
r.w = 2;
r.h = 3;
printShape(r); // Prints: rect: 6.000000
```

لوراثة صنف دون استبدال أي من دالاته الافتراضية أو إضافة دالات جديدة استخدم الشكل المختصر `نـبك.اشتق_صنفا[شكل، شـكل]`.

**خلف الكواليس:** يضيف `اشتق_صنفا` متغيرا عضوا محقونا اسمه `شكل` من صنف `شـكل`، ولهذا تكون أعضاء `شـكل` متاحة على
`مـستطيل` ويُقبل `مـستطيل` كـ`شـكل`. كما يعرّف صنف جدول دالات جديدا لـ`مـستطيل` اسمه أيضا `جـدول`، يحتوي جدول دالات
`شـكل` في متغير عضو اسمه `شكل`، لذا فإن `هذا.شكل.المساحة` في دالة الاستبدال تشير إلى المؤشر `المساحة` الموروث من
`شـكل`. تُملأ نسخة مشتركة من جدول الدالات هذا بنسخ `مـستطيل` من الدالات، ويجعل منشئ `مـستطيل` المتغير `شكل.جدول`
يشير إليها. بهذا يصل الاستدعاء عبر `سند[شـكل]` إلى نسخ `مـستطيل`: فالاستدعاء يمر عبر `شكل.جدول` الذي صار يشير إلى جدول
دالات `مـستطيل`. أما دالات `مـستطيل` نفسه، سواء الجديدة مثل `مربع_القطر` أو البديلة مثل `_المساحة`
العائدة له، فيُوصل إليها عبر خاصية محقونة تعطي جدول دالات `مـستطيل`.

## استدعاء نسخة الصنف الأب

يمكن للدالة التي تستبدل دالة من الصنف الأب أن تستدعي نسخة الصنف الأب بإضافة شرطة سفلية قبل اسم الدالة:

```
صنف مـستطيل {
    نـبك.اشتق_صنفا[شكل، شـكل، جدول، جـدول]؛
    ...
    ضمن جـدول عملية هذا.شكل.صف() حدد_مؤشر {
        طـرفية.اطبع("مستطيل: ")؛
        هذا.شكل._صف()؛ // يستدعي نسخة شـكل.
    }
}
```

```
class Rect {
    Oop.inheritClass[shape, Shape, vtable, VTable];
    ...
    within VTable handler this.shape.describe() set_ptr {
        Console.print("Rect: ");
        this.shape._describe(); // Calls Shape's version.
    }
}
```

**خلف الكواليس:** الدالة الافتراضية التي لها متن، والمعرفة باستخدام `كمؤشر` أو `حدد_مؤشر`، تُعرّف كوظيفة عادية
يتكون اسمها من اسم الدالة مسبوقا بشرطة سفلية، ويُجعل مؤشر الدالة يشير إلى تلك الوظيفة. استدعاء `هذا.شكل._صف()`
يستدعي وظيفة `شـكل` مباشرة بدل المرور عبر مؤشر الدالة، لذا فهو ينفذ نسخة `شـكل` دائما.

## وراثة صنف مشتق

الصنف الذي يرث صنفا مشتقا بدوره، مثل `مـربع` الذي يرث `مـستطيل`، يستخدم الشكل الطويل من `نـبك.اشتق_صنفا` الذي يستلم ستة
أسماء:

* اسما للمتغير العضو الذي يحمل جزء الصنف الأب، مثل `مستطيل`.
* الصنف الأب، مثل `مـستطيل`.
* متغير جدول دالات الصنف الأب، مثل `مستطيل.جدول`. هذا دائما اسم المتغير العضو الجديد متبوعا بـ`.` ثم الاسم الأول
  المعطى لـ`عرف_جدول_دالات` في الصنف الأعلى.
* صنف جدول دالات الصنف الأب، مثل `مـستطيل.جـدول`.
* اسما لجدول دالات الصنف الجديد، مثل `جدول_مشترك`.
* اسما لصنف جدول دالات الصنف الجديد، مثل `جـدول`.

لاستبدال دالة ابدأ من `هذا` ومر عبر أسماء المتغيرات الأعضاء وصولا إلى الصنف الذي عرّف الدالة أولا. على سبيل المثال،
عُرّفت `المساحة` أولا في `شـكل`، لذا يستبدلها `مـربع` بـ`هذا.مستطيل.شكل.المساحة()`، بينما عُرّفت `مربع_القطر` أولا
في `مـستطيل`، لذا يستبدلها `مـربع` بـ`هذا.مستطيل.مربع_القطر()`:

```
صنف مـربع {
    نـبك.اشتق_صنفا[مستطيل، مـستطيل، مستطيل.جدول، مـستطيل.جـدول، جدول_مشترك، جـدول]؛

    ضمن جـدول عملية هذا.مستطيل.شكل.المساحة(): عائم[64] حدد_مؤشر {
        أرجع هذا.العرض * هذا.العرض؛
    }

    ضمن جـدول عملية هذا.مستطيل.مربع_القطر(): عائم[64] حدد_مؤشر {
        أرجع هذا.العرض * هذا.العرض * 2؛
    }
}
```

```
class Square {
    Oop.inheritClass[rect, Rect, rect.vtable, Rect.VTable, svtable, VTable];

    within VTable handler this.rect.shape.area(): Float[64] set_ptr {
        return this.w * this.w;
    }

    within VTable handler this.rect.diagonal2(): Float[64] set_ptr {
        return this.w * this.w * 2;
    }
}
```

استدعاء نسخة الصنف الأب يعمل كما في القسم السابق: `هذا.مستطيل._المساحة()` يستدعي نسخة `مـستطيل` من `المساحة`،
و`هذا.مستطيل._مربع_القطر()` يستدعي نسخة `مـستطيل` من `مربع_القطر`. إذا لم يستبدل الصنف الأب الدالة يذهب الاستدعاء إلى
نسخة أقرب سلف لديه نسخة منها. ولتخطي نسخة الصنف الأب واستدعاء نسخة سلف أبعد أكمل المسار، كما في
`هذا.مستطيل.شكل._صف()`، الذي يستدعي نسخة `شـكل` رغم أن `مـستطيل` استبدلها.

**خلف الكواليس:** يحتوي كل صنف جدولَ دالات صنفه الأب في متغير عضو يحمل اسم المتغير العضو الذي يحمل
الصنف الأب، لذا فإن مسار الدالة في جداول الدالات يطابق المسار عبر الكائنات، كما في `هذا.مستطيل.شكل.المساحة`. يحصل كل
صنف على خاصية محقونة تعطي جدول دالاته، وتوضع هذه الخاصية في بداية الصنف قبل المتغير العضو الذي يحمل الصنف الأب، لذا
فإن البحث عن `_المساحة` في `هذا.مستطيل` يبحث في جدول دالات `مـستطيل`، الذي يحتوي `_المساحة` العائدة لـ`مـستطيل`، قبل
المرور عبر المتغير `شكل` إلى جدول دالات `شـكل`. المتغير العضو الذي يحمل جدول دالات الصنف الأب غير محقون، لذا لا يدخل هذا
البحث إلى جدول دالات الصنف الأب، فتبقى أسماء مثل `شكل` مشيرة إلى الكائنات لا إلى جداول الدالات.

## وراثة عدة أصناف

يمكن للصنف أن يرث أكثر من صنف ذي دالات افتراضية. استخدم الشكل الطويل من `نـبك.اشتق_صنفا` لكل صنف أب، وأعط جدول دالات كل
صنف أب أسماءه الخاصة:

```
صنف مـتعدد {
    نـبك.اشتق_صنفا[أساس1، أسـاس1، أساس1.جدول، أسـاس1.جـدول، جدول_مشترك1، جـدول1]؛
    نـبك.اشتق_صنفا[أساس2، أسـاس2، أساس2.جدول، أسـاس2.جـدول، جدول_مشترك2، جـدول2]؛

    ضمن جـدول1 عملية هذا.أساس1.هات1(): صحيح حدد_مؤشر {
        أرجع هذا.أ * 10؛
    }

    ضمن جـدول2 عملية هذا.أساس2.هات2(): صحيح حدد_مؤشر {
        حاذ_هذا[أساس2، مـتعدد]؛
        أرجع هذا.أ + هذا.ب * 10؛
    }
}
```

```
class Multi {
    Oop.inheritClass[base1, Base1, base1.vtable, Base1.VTable, svtable1, VTable1];
    Oop.inheritClass[base2, Base2, base2.vtable, Base2.VTable, svtable2, VTable2];

    within VTable1 handler this.base1.get1(): Int set_ptr {
        return this.i * 10;
    }

    within VTable2 handler this.base2.get2(): Int set_ptr {
        alignThis[base2, Multi];
        return this.i + this.j * 10;
    }
}
```

هناك قاعدتان يجب مراعاتهما:

* الدالات التي تستبدل دالات أي صنف أب غير الأول يجب أن تبدأ بـ`حاذ_هذا[متغير، صنف]` (`alignThis`)، حيث `متغير` هو
  اسم المتغير العضو الذي يحمل ذلك الصنف الأب و`صنف` هو الصنف الجاري تعريفه، كما في `حاذ_هذا[أساس2، مـتعدد]` في المثال
  السابق.
* الصنف الأب الأول فقط يُقبل تلقائيا حيثما يُتوقع سند إلى صنف أب. أما بقية الأصناف الأب فمرر المتغير العضو الذي يحمل
  الصنف الأب، كما في `اعرض_أساس2(م.أساس2)`.

لوراثة صنف له عدة أصناف أب ذات دالات افتراضية استخدم الشكل المختصر من `نـبك.اشتق_صنفا` لوراثة الصنف، ثم أضف
`نـبك.اشتق_جدول_دالات` (`Oop.inheritVTable`) لكل جدول من جداول دالاته. يستلم `نـبك.اشتق_جدول_دالات` نفس الأسماء الستة
التي يستلمها الشكل الطويل من `نـبك.اشتق_صنفا`:

```
صنف مـتعدد_مشتق {
    نـبك.اشتق_صنفا[متعدد، مـتعدد]؛
    نـبك.اشتق_جدول_دالات[متعدد، مـتعدد، أساس1.جدول، مـتعدد.جـدول1، جدول_مشترك1، جـدول1]؛
    نـبك.اشتق_جدول_دالات[متعدد، مـتعدد، أساس2.جدول، مـتعدد.جـدول2، جدول_مشترك2، جـدول2]؛

    ضمن جـدول1 عملية هذا.متعدد.أساس1.هات1(): صحيح حدد_مؤشر {
        أرجع هذا.أ * 100؛
    }

    ضمن جـدول2 عملية هذا.متعدد.أساس2.هات2(): صحيح حدد_مؤشر {
        حاذ_هذا[أساس2، مـتعدد_مشتق]؛
        أرجع هذا.أ + هذا.ب * 100؛
    }
}
```

```
class MultiChild {
    Oop.inheritClass[multi, Multi];
    Oop.inheritVTable[multi, Multi, base1.vtable, Multi.VTable1, svtable1, VTable1];
    Oop.inheritVTable[multi, Multi, base2.vtable, Multi.VTable2, svtable2, VTable2];

    within VTable1 handler this.multi.base1.get1(): Int set_ptr {
        return this.i * 100;
    }

    within VTable2 handler this.multi.base2.get2(): Int set_ptr {
        alignThis[base2, MultiChild];
        return this.i + this.j * 100;
    }
}
```

**خلف الكواليس:** يُخزن جزء كل صنف أب في موقع خاص به داخل الكائن، ولكل منها متغير جدول دالات خاص به، ولهذا يحتاج كل
صنف أب لصنف جدول دالات ونسخة مشتركة خاصين به. عند استدعاء دالة عبر سند إلى الصنف الأب الثاني يشير `هذا` إلى المتغير
العضو `أساس2`، وهو ليس في بداية الكائن. يُرجع `حاذ_هذا` المؤشر `هذا` بمقدار موقع ذلك المتغير العضو فيعود ليشير إلى
بداية الكائن. ولا يُقبل تلقائيا كسند إلى الصنف الأب إلا الصنف الأب الأول لأن المترجم لا يستخدم إلا المتغير المحقون
الأول عند تحويل كائن إلى صنف أحد أعضائه.

## الماكروهات

### عرف_جدول_دالات (defVtable)

```
ماكرو عرف_جدول_دالات [جدول، جـدول]
```

```
macro defVtable [vtable, VTable]
```

يضيف دعم الدالات الافتراضية إلى صنف. `جدول` و`جـدول` هما الاسمان المستخدمان للإشارة إلى جدول الدالات في الصنف وفي
الأصناف المشتقة. تُعرّف الدالات الافتراضية بعد ذلك بالصيغة `ضمن جـدول عملية ... كمؤشر`.

**خلف الكواليس:** يعرّف صنف جدول الدالات `جـدول`، ونسخة مشتركة منه اسمها حرف `s` متبوعا بـ`جدول` (أي `sجدول`)،
ومتغيرا عضوا محقونا ومعلَّما بـ`دون_ربط` اسمه `جدول` يشير إلى النسخة المشتركة.

### اشتق_صنفا (inheritClass)

```
ماكرو اشتق_صنفا [أساس، أسـاس]
ماكرو اشتق_صنفا [أساس، أسـاس، جدول، جـدول]
ماكرو اشتق_صنفا [أساس، أسـاس، جدول_الأساس، جـدول_الأساس، جدولي_المشترك، جـدولي]
```

```
macro inheritClass [base, Base]
macro inheritClass [base, Base, vtable, VTable]
macro inheritClass [base, Base, baseVtable, BaseVTable, mySharedVtable, MyVTable]
```

يرث الصنف `أسـاس` ويخزن جزءه من الكائن في متغير عضو اسمه `أساس`.

* الشكل المختصر يرث الصنف دون استبدال دالات افتراضية أو إضافة دالات جديدة.
* الشكل الثاني يسمح للصنف المشتق أيضا باستبدال الدالات الافتراضية وإضافة دالات جديدة. `جدول` و`جـدول` هما الاسمان
  المعطيان لـ`عرف_جدول_دالات` في `أسـاس`. تُعرّف الدالات بالصيغة `ضمن جـدول عملية ...` في الصنف المشتق.
* الشكل الطويل مطلوب عند وراثة صنف مشتق أو عدة أصناف. `جدول_الأساس` و`جـدول_الأساس` هما متغير جدول دالات الصنف الأب
  وصنفه، و`جدولي_المشترك` و`جـدولي` اسمان لجدول دالات الصنف الجديد. تُعرّف الدالات بالصيغة `ضمن جـدولي عملية ...` في
  الصنف المشتق.

**خلف الكواليس:** يعرّف متغيرا عضوا محقونا اسمه `أساس` من صنف `أسـاس`. الشكل الثاني مكافئ لـ
`اشتق_جدول_دالات[أساس، أسـاس، أساس.جدول، أسـاس.جـدول، sجدول، جـدول]`، حيث `sجدول` هو حرف `s` متبوعا بـ`جدول`، أما
الشكل الطويل فمكافئ للشكل المختصر متبوعا بـ`اشتق_جدول_دالات` بنفس المعطيات.

### اشتق_جدول_دالات (inheritVTable)

```
ماكرو اشتق_جدول_دالات [أساس، أسـاس، جدول_الأساس، جـدول_الأساس، جدولي_المشترك، جـدولي]
```

```
macro inheritVTable [base, Base, baseVtable, BaseVTable, mySharedVtable, MyVTable]
```

يسمح للصنف باستبدال الدالات الافتراضية وإضافة دالات جديدة لأحد جداول دالات صنف أب سبقت وراثته بالشكل المختصر من
`اشتق_صنفا`. معطياته هي نفس معطيات الشكل الطويل من `اشتق_صنفا`. يُستخدم عند وراثة صنف له عدة أصناف أب ذات دالات
افتراضية.

**خلف الكواليس:** يعرّف صنف جدول الدالات `جـدولي` الذي يحتوي `جـدول_الأساس` في متغير عضو اسمه `أساس`، ونسخة
مشتركة منه اسمها `جدولي_المشترك`. يجعل منشئ الصنف `جدول_الأساس` يشير إلى `جدولي_المشترك`. كما يضيف في بداية الصنف،
أينما استُخدم الماكرو، خاصية محقونة ومعلَّمة بـ`دون_ربط` تحمل اسم `جدولي_المشترك` متبوعا بـ`Ref`، تعطي سندا إلى جدول
الدالات كـ`جـدولي`، مما يجعل دالات الصنف الافتراضية الخاصة به متاحة على الكائن.

## الأخطاء

* `SRT1004`: دالة تستبدل دالة عبر متغير عضو غير موجود في الصنف، كما في `هذا.غير_موجود.د()`. تأكد من أن اسم المتغير
  العضو يطابق الاسم الأول المعطى لـ`اشتق_صنفا`.
* `SRT1005`: استُخدم `عرف_جدول_دالات` أو `اشتق_جدول_دالات` أو أحد أشكال `اشتق_صنفا` التي تستلم أسماء جداول الدالات خارج
  متن صنف. لا يمكن استخدام هذه الماكروهات إلا داخل متن الصنف الذي تُطبق عليه.
